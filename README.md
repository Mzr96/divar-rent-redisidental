# کرال آگهی‌های اجاره دیوار

آگهی‌های اجاره را از دیوار می‌خواند، آگهی‌های تکراری یک خانه را یکی می‌کند،
از هر خانه فقط ارزان‌ترین نسخه را نشان می‌دهد و یک گزارش HTML می‌سازد.
اگر تلگرام را تنظیم کنی، خانه‌های جدید و قیمت‌های بهتر را هم پیام می‌دهد.

## راه‌اندازی

```
pip install requests pillow
python divar_rent.py              # یک بار
python divar_rent.py --loop 30    # هر ۳۰ دقیقه
```

بعد `report.html` را در مرورگر باز کن.

## تنظیم جست‌وجو (config.json)

1. در divar.ir شهر و دسته (مثلاً «اجاره آپارتمان») را باز کن و فیلترها را بزن:
   محله، ودیعه، اجاره، متراژ و غیره. محله را از فیلتر «محله» انتخاب کن، یا روی نقشه
   محدوده را جابه‌جا کن و «جست‌وجو در این محدوده» را بزن تا `bbox=` در آدرس بیاید.
2. آدرس صفحه را از نوار مرورگر کپی کن و در `search_urls` بگذار. چند آدرس هم می‌شود.

فیلترهای آدرس به API دیوار فرستاده می‌شوند. اگر دیوار فیلتری را نپذیرفت، اسکریپت فقط
با دسته و محله (یا محدوده‌ی نقشه) جست‌وجو می‌کند؛ برای همین بهتر است سقف‌ها را در بخش `filters` هم بنویسی
(به تومان). این فیلترها همیشه سمت خود اسکریپت اعمال می‌شوند.

| تنظیم | توضیح |
|---|---|
| `conversion_rate_monthly` | نرخ تبدیل ودیعه به اجاره در ماه. ۰٫۰۳ یعنی هر ۱۰۰ میلیون ودیعه = ۳ میلیون اجاره. با نرخ بازار شهر خودت تنظیمش کن. |
| `max_pages` | چند صفحه (هر صفحه حدود ۲۴ آگهی) از هر آدرس خوانده شود. |
| `exclude_terms` | آگهی‌هایی که این کلمه‌ها را دارند حذف می‌شوند. |
| `exclude_agencies` | `true` یعنی فقط آگهی‌های شخصی. |
| `min_plausible_monthly_cost` | قیمت‌های کمتر از این (مثلاً «۱ تومان» برای جلب توجه) غیرواقعی حساب می‌شوند و ارزان‌ترین انتخاب نمی‌شوند. |

## تشخیص تکراری

دو آگهی یک خانه حساب می‌شوند اگر:
- عکس‌هایشان یکی باشد (حتی کراپ‌شده یا با کیفیت متفاوت)، یا
- متراژ، تعداد اتاق، سال ساخت و طبقه‌شان بخواند و متن توضیحاتشان شبیه باشد.

اگر طبقه یا تعداد اتاق دو آگهی فرق کند، یکی نمی‌شوند؛ مگر اینکه دست‌کم سه عکسشان یکی باشد.
آگهی‌های دیگر هر خانه زیر کارتش آمده‌اند تا بتوانی مقایسه کنی.

## تلگرام (اختیاری)

یک ربات با @BotFather بساز، توکنش را در `bot_token` و شناسه‌ی چتت را در `chat_id` بگذار؛
ترجیحاً در فایل `config.local.json` که در git نیست و روی `config.json` اعمال می‌شود:

```json
{"telegram": {"bot_token": "123:ABC...", "chat_id": "123456"}}
```

اجرای اول فقط پایه را ثبت می‌کند. از اجرای دوم به بعد فقط برای خانه‌های واقعاً جدید
یا خانه‌ای که نسخه‌ی ارزان‌تری از آن آمده پیام می‌آید. هر پیام چند عکس آگهی را
به‌صورت آلبوم دارد؛ تعدادش را با `max_photos` تعیین کن (۰ یعنی بدون عکس، حداکثر ۱۰). اگر تلگرام روی شبکه‌ات باز نیست،
متغیر محیطی `HTTPS_PROXY` را تنظیم کن یا اسکریپت را روی یک سرور اجرا کن.

## اجرا روی GitHub Actions (رایگان)

`.github/workflows/crawl.yml` اسکریپت را هر ۳۰ دقیقه روی سرورهای گیت‌هاب اجرا می‌کند.
ریپازیتوری باید public باشد تا دقیقه‌های Actions محدودیت نداشته باشد.

1. در Settings → Secrets and variables → Actions دو secret بساز:
   `TELEGRAM_BOT_TOKEN` و `TELEGRAM_CHAT_ID`. توکن را هرگز در `config.json` نگذار.
2. از تب Actions، workflow «crawl» را با Run workflow یک بار دستی اجرا کن.

دیتابیس و `report.html` بعد از هر اجرا در شاخه‌ی `data` ذخیره می‌شوند و اجرای بعدی از همان‌جا
ادامه می‌دهد. اگر شاخه‌ی `data` نباشد، اجرای بعدی فقط پایه را ثبت می‌کند و پیامی نمی‌فرستد.
اگر گیت‌هاب بعد از ۶۰ روز بی‌فعالیتی زمان‌بندی را غیرفعال کرد، از همان تب Actions دوباره فعالش کن.

## محدودیت‌ها

- از endpointهای غیررسمی وب‌اپ دیوار استفاده می‌کند. اگر دیوار ساختارش را عوض کند،
  ممکن است بخشی از کد نیاز به اصلاح داشته باشد.
- برای استفاده‌ی شخصی است. فاصله‌ی بین درخواست‌ها را کم نکن.
